# 04 MVP 验证计划

> 目标：用**最少的钱**回答"这盏灯值不值得做"，而不是"能不能做出来"。
> 本计划的每个结论都必须有数字支撑；"用户说挺好"不算结论。

---

## 一、验证框架：三轮，串行，每轮有否决权

```
第一轮（M1–M2）  红外学习 + 照明
      │  问题：用户愿不愿意学？学得会吗？
      │  ↓ 不通过 → 停止，或改走"内置码库"路线
第二轮（M2–M4）  定时 + 灯光/红外联动（±动作反馈）
      │  问题：提醒会被重复使用，还是新鲜三天？
      │  ↓ 不通过 → 砍掉定时，把资源投入红外体验打磨
第三轮（M4–M6）  动作与语音深度（按前两轮数据决定做多少）
      │  问题：动作是加分还是干扰？语音比按键更方便吗？
      │  ↓ 不通过 → 只保留低成本动作，不做语音
```

**串行而非并行**的三个理由：
1. 并行会让"需求不成立"与"工程做不出来"两个失败原因混在一起，无法归因；
2. 每加一层，BOM +25~50 元、售后问题类型 +1 类；
3. 小团队的人力只够把一件事做透。

## 二、第一轮：红外学习 + 照明

### 2.1 要验证的假设

| 编号 | 假设 | 指标 | 通过阈值 | 数据来源 |
|------|------|------|----------|----------|
| R1-1 | 用户能独立完成学习 | 无指导完成 4 键学习的人数 | ≥ 16/20 | 现场观察 |
| R1-2 | 学习动作耗时可接受 | 中位时长 | ≤ 90 秒 | 计时 |
| R1-3 | 学习结果可靠 | 首次学习成功率 | ≥ 90% | 设备日志 |
| R1-4 | 回放能真正控制家电 | 发射后家电响应的比例 | ≥ 95% | 现场验证 |
| R1-5 | 照明体验不拖后腿 | 与用户现用台灯对比评分 | ≥ 3.5/5 | 问卷 |
| R1-6 | 用户会重复使用 | 2 周内人均红外使用次数 | ≥ 3 次/周 | 设备日志 |

### 2.2 样机与样本

| 项 | 内容 |
|----|------|
| 样机数量 | 20 台（手工焊 + 3D 打印外壳） |
| 用户 | 4 间宿舍 × 5 人（优先有空调的宿舍） |
| 遥控器 | 至少覆盖 5 品牌：格力、美的、海尔、奥克斯 + 1 进口 |
| 周期 | 14 天（含 1 次中期回访） |
| 激励 | 免费用 + 50 元红包（避免"人情好评"：红包在归还样机后发放） |

### 2.3 现场测试协议（每人 20 分钟，全程不提示）

```
0–2 min   说明："这是一个台灯，它能学遥控器。请你自己试试让它控制空调。"
          然后闭嘴，只记录（不说"长按 3 秒"这类提示）。
2–12 min  观察并记录：
          - 第一次成功前尝试了几次？
          - 在哪里卡住（找不到按键 / 不知道对准 / 以为坏了）？
          - 是否看了说明书？（说明书放在桌上，不主动递）
12–15 min 若仍未成功，给最小提示（只说"长按学习键"），继续记录。
15–20 min 问卷 + 半结构访谈（见 02 文档脚本）。
```

**关键纪律**：主持人**不得**在用户失败前提供帮助，否则 R1-1 的数据全废。

### 2.4 设备日志字段（第一轮就要埋）

| 事件 | 字段 | 用途 |
|------|------|------|
| `boot` | 固件版本、复位原因 | 排除"死机被误认为难用" |
| `learn_start` | slot、时间戳 | 计算学习耗时 |
| `learn_result` | ok、reason（too_short/unstable/crc/timeout） | 定位失败原因分布 |
| `ir_send` | slot、ok | 计算使用频次（R1-6） |
| `light_set` | 亮度、色温 | 判断照明是否被使用 |
| `power_cycle` | 次数 | 发现"拔电重启"这类隐藏故障 |

### 2.5 第一轮否决条件（任一触发即停止投入）

| 条件 | 含义 | 处置 |
|------|------|------|
| 无指导完成率 < 50% | 学习动作本身就是门槛 | 改用"内置码库 + 扫码选机型" |
| 2 周人均使用 < 1 次/周 | 不是刚需，是玩具 | 停止，重新找入口 |
| 首次学习成功率 < 80% 且无明确改进路径 | 技术不可行 | 换接收头/改电路后再测一次，仍失败则停止 |
| 照明评分 < 3.0/5 | 底座不牢 | 先修照明，功能再好也没用 |

## 三、第二轮：定时 + 联动

### 3.1 假设与指标

| 编号 | 假设 | 指标 | 阈值 |
|------|------|------|------|
| R2-1 | 定时会被重复使用 | 14 天内创建 ≥ 2 个任务的用户比例 | ≥ 40% |
| R2-2 | 提醒不会被关掉 | 第 14 天仍启用任务的比例 | ≥ 50% |
| R2-3 | "定时 + 关空调"联动有价值 | 使用过联动的用户比例 | ≥ 25% |
| R2-4 | 动作反馈是加分 | "动作有用"评分 | ≥ 3.5/5，且想常关者 ≤ 20% |
| R2-5 | 动作不干扰 | 夜间被投诉/主动静音的比例 | ≤ 30% |

### 3.2 测试设计

**A/B 两组，各 10 台**：
- A 组：定时仅灯光提示（无动作）
- B 组：定时灯光 + 1 次点头动作

对比指标：任务启用率、主动关闭率、主观评分。
**这是判断"动作值不值 30 元 BOM"的唯一干净实验**，不要用"大家都说可爱"代替。

### 3.3 典型任务卡（给用户，不解释）

| 卡片 | 内容 |
|------|------|
| 1 | "明天早上 7 点，让灯慢慢亮起来。" |
| 2 | "45 分钟后提醒我休息一下。" |
| 3 | "晚上 11 点，提醒我并帮我关空调。" |
| 4 | "把这个提醒取消。" |

观察：能否独立完成、需要几次尝试、是否误删其他任务。

### 3.4 第二轮否决条件

- R2-1 < 25%：定时是伪需求 → 砍掉，节约 OLED 与按键成本（BOM −11.7 元）；
- R2-4 < 3.0 或想常关者 > 35%：动作是负资产 → Pro 版取消动作，只做 Plus；
- 夜间投诉 > 40%：静音策略失效 → 必须先修好再谈情绪价值。

## 四、第三轮：语音与深度互动（条件触发）

**只有当前两轮都通过才进入**，否则不投人。

| 编号 | 假设 | 指标 | 阈值 |
|------|------|------|------|
| R3-1 | 窄域语音比按键方便 | 语音使用占比（vs 按键） | ≥ 25% |
| R3-2 | 识别可用 | 一次说对成功率 | ≥ 85% |
| R3-3 | 误唤醒可接受 | 每小时误触发次数（电视播放中） | ≤ 1 次/h |
| R3-4 | 语音带来溢价 | 愿意为语音多付的金额中位数 | ≥ 50 元 |

### 4.1 语音测试的特殊要求

- 必须在**有电视/音箱播放人声**的环境测试误唤醒，安静房间的数据没有意义；
- 必须测试**方言口音**（至少 3 种），LD3320 对普通话要求较高，口音重时成功率会掉到 60% 以下；
- 结论若为"语音只在安静环境好用"，就**不要做语音**——宿舍与办公室都不安静。

## 五、数据采集与分析

### 5.1 数据管道（无需服务器）

```
设备 → USB 串口导出 CSV（售后/回访时） → 本地 Python 脚本汇总 → 指标表
```

**为什么不联网上传**： MVP 阶段量小（20 台），联网方案要处理隐私、服务器、断网，
成本远高于收益；且用户对"台灯联网上传数据"天然警惕。

### 5.2 必须产出的三张表

| 表 | 内容 | 用途 |
|----|------|------|
| 学习失败归因表 | reason 分布（too_short / unstable / crc / timeout）× 品牌 | 决定改电路还是改交互 |
| 使用频次表 | 每用户每日 ir_send / timer_fire / light_set 次数 | 判断刚需强度 |
| 关闭行为表 | 静音、关动作、删任务的比例与时点 | 判断哪些功能是负资产 |

### 5.3 统计口径（写死，防止事后解释）

- "活跃用户" = 当天有 ≥1 次 `ir_send` 或 `timer_fire`；
- "周使用次数" = 7 天内事件总数 ÷ 7；
- 剔除前 2 天（新鲜期）再计算稳态指标；
- 样本 < 20 时只报中位数与分布，不报均值（避免被极端值带偏）。

## 六、排期与预算

| 周 | 任务 | 花费 |
|----|------|------|
| W1 | 物料采购（5 台）+ 面包板验证 | 900 元 |
| W2 | 固件初版（IR + 照明 + CLI） | — |
| W3 | 3D 打印外壳 + 装配 20 台 | 6,000 元 |
| W4 | 现场测试（4 间宿舍）+ 访谈 | 2,000 元（含红包） |
| W5 | 数据分析 + 第一轮结论 | — |
| W6–W8 | 定时/动作版本 + A/B 测试 | 3,000 元 |
| **合计** | | **≈12,000 元** |

> 对比：直接开模做 300 台约需 7–8 万元。**先用 1.2 万证伪，是最便宜的保险。**

## 七、结论模板（每轮结束必须填，不允许只写"效果不错"）

```markdown
## 第 N 轮验证结论
- 样本：__ 人 / __ 台 / __ 天
- R?-1 指标值：__（阈值 __）→ 通过 / 不通过
- R?-2 指标值：__（阈值 __）→ 通过 / 不通过
- 最大意外发现：__
- 与原假设冲突之处：__
- 决策：继续 / 修正后继续 / 停止
- 若继续，下一轮要改的一件事：__
```

**填不出"最大意外发现"，说明这轮测试设计有问题**——只验证自己相信的东西，等于没验证。
