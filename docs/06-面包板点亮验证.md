# 06 面包板点亮验证：按键开灯（GPIO4 / GPIO5）

> 目标：用现有开发板 + HW-483 按键模块 + HW-479 RGB 模块，**先跑通"按一下灯亮、再按一下灯灭"**。
> 这是整台灯最小的一条闭环，跑通之后再谈 PWM 调光、长按、红外。
>
> 状态：电气连通 + 逻辑验证。不涉及 EMC、热、寿命，也不代表成品 PCB 的接法。

## 1. 先说清楚：现有固件不能直接烧

`firmware/src/main.cpp` 是给**成品 PCB** 写的骨架，和现在这块面包板对不上：

| 项目 | 现有固件（config.h） | 现在面包板上 |
|------|----------------------|--------------|
| GPIO4 / GPIO5 | `PIN_LED_WARM` / `PIN_LED_COOL`，LEDC 4 kHz PWM 驱动照明 | 按键信号 / RGB 模块 G 通道 |
| 按键 | GPIO13 / 14 / 15（`PIN_BTN_MODE` 等） | GPIO4 |
| 依赖 | IRremoteESP8266、ArduinoJson、LittleFS、舵机 PWM | 只需要 Arduino 核心 |

直接烧 `main.cpp`：能编译，但按键永远读不到、灯不会亮、两个舵机通道还会按 50 Hz 输出乱动。
所以先烧一份独立的 bring-up 固件：`firmware/src/bringup/main.cpp`，编译环境 `[env:bringup]`。

## 2. 接线核对表（按顺序核，5 分钟）

| # | 从 | 到 | 怎么确认 |
|---|----|----|----------|
| 1 | ESP32 `3V3` | 面包板红轨（+） | 万用表直流档量红轨对蓝轨：**3.25 ~ 3.35 V** |
| 2 | ESP32 `GND` | 面包板蓝轨（−） | 同上；顺便量模块的 `-` 与 ESP32 GND 应导通 |
| 3 | HW-483 `+` | 红轨 | 模块丝印为准，**不要只按线的颜色认** |
| 4 | HW-483 `-` | 蓝轨 | |
| 5 | HW-483 `S` | ESP32 `GPIO4`（认丝印 `4`，不认位置） | 烧 MODE 1，按下应打印 `raw=0` |
| 6 | HW-479 `-` | 蓝轨 | 公共端，必须共地 |
| 7 | HW-479 `G` | ESP32 `GPIO5`（认丝印 `5`） | 烧 MODE 0，应 1 Hz 闪烁 |
| 8 | HW-479 `R` `B` | 悬空 | 本次不用 |

### 三个最容易踩的坑

1. **HW-479 的针序是 `- R G B`**，从有 `-` 丝印的那一端数第 1 脚。
   棕线插在第 2 脚（R）上，绿灯永远不亮 —— 这是本次接线里最可能的失败点。
   照片里模块右侧四根针从上到下就是 `- / R / G / B`，把棕线对到**第 3 根**。
2. **面包板电源轨中间可能是断开的**（830 孔板常见）。3V3 从左边送进去，模块在右边取电就可能没电。
   红轨两端各量一次，或把 3V3、GND 各补一根线到右半段。
3. **GPIO4 / GPIO5 不是 strapping 脚**，上电不会影响启动模式，可以放心用；
   但别顺手挪到 GPIO0 / 3 / 45 / 46（strapping）或 19 / 20（USB D−/D+）。

### 一条 30 秒的分界线

怀疑"是程序没跑，还是线没通"时：烧 MODE 0，万用表黑表笔接 GND、红表笔点 GPIO5。
- 0 V ↔ 3.3 V 每秒跳变 → 软件没问题，去查灯那一段线；
- 一直是 0 V 或一直是 3.3 V → 程序没跑起来（或引脚号错），先解决烧录。

## 3. 三步验证

改 `firmware/src/bringup/main.cpp` 顶部的 `BRINGUP_MODE`，每次改完重新烧录。

| 步骤 | `BRINGUP_MODE` | 期望现象 | 不符合怎么办 |
|------|----------------|----------|--------------|
| ① 只点灯 | `0` | 灯 1 Hz 闪；开机时先闪 2 下 | 看第 4 节第 1~3 行 |
| ② 只看键 | `1` | 串口：松开 `raw=1`，按下 `raw=0` | 看第 4 节第 4~6 行 |
| ③ 合起来 | `2` | 每按一下翻转一次，串口打印 `pressed -> LED ON/OFF` | 抖动就加大 `DEBOUNCE_MS` |

开机自检会先闪 2 次灯：**灯不闪就不用往下看了**，先把灯那一侧弄通。

## 4. 排错表

| 症状 | 最可能的原因 | 处理 |
|------|--------------|------|
| 串口一个字都没有 | 插错 Type-C 口 / USB CDC 设置不对 / 没装 CP2102 驱动 | 换另一个口再试；Arduino IDE 里 `USB CDC On Boot` 与所用端口匹配（UART 口 = Disabled）；设备管理器看有没有新 COM |
| 灯常亮不闪 | GPIO5 短到 3V3，或模块是共阳接法 | 拔掉棕线看是否还亮；共阳则公共端改接 3V3 并设 `LED_ACTIVE_HIGH 0` |
| 灯完全不亮 | 棕线插在 R/B 上；`-` 没接地；电源轨断开 | 按第 2 节逐条量；先把棕线换到相邻脚试 |
| 灯很暗但能看到 | 限流电阻偏大 / 用了 R 或 B 通道（压降不同） | 确认插的是 G；属正常范围，模块自带 150 Ω |
| 按下没反应，`raw` 恒为 1 | `S` 没插到底 / 模块 `+` 没电 / 模块是下拉型 | 量模块 `+` 对 `-` 是否 3.3 V；下拉型把 `BTN_USE_PULLUP` 改 `0` |
| `raw` 恒为 0 | `S` 与 GND 短路，或模块 `-` 没接 | 拔掉 `S` 线看是否变 1 |
| 按下是 1、松开是 0 | 模块是下拉型（或 `+`/`-` 接反） | `BTN_ACTIVE_LOW` 改 `0`，或把红黑线对调 |
| 按一下亮两下 | 机械抖动 | `DEBOUNCE_MS` 从 25 加到 40~50 |
| 上传失败 `Failed to connect` | 没进下载模式 | 按住 `BOOT` → 点一下 `RST` → 松开 `BOOT` → 再上传；仍失败就把 `upload_speed` 降到 115200 |

## 5. 烧录

### PlatformIO（仓库默认）

```bash
pip install platformio          # 本机还没装
cd firmware
pio run -e bringup -t upload
pio device monitor -b 115200
```

`[env:bringup]` 用 `build_src_filter = +<bringup/>` 只编这一个文件，不会把 IR / 舵机那些模块带进来。

### Arduino IDE

1. 把 `firmware/src/bringup/main.cpp` 复制成 `button_led/button_led.ino`（文件夹名必须和 .ino 同名）。
2. 开发板选 **ESP32S3 Dev Module**；端口选插上后新出现的 COM（两个 Type-C 口各试一次）。
3. `USB CDC On Boot`：用标着 UART 的口选 **Disabled**，用 USB 口选 **Enabled**。
4. Flash Size / PSRAM 保持默认即可，这个程序用不到。
5. 上传失败就按上面表格最后一行的 BOOT + RST 组合。

## 6. 跑通之后怎么并回正式固件

1. **引脚要重新分配**：`config.h` 里 GPIO4/5 已经是暖白/冷白 PWM 通道，正式板上按键走
   `PIN_BTN_LIGHT = 14`。面包板这套接法只是验证"人按 → 电信号 → 灯亮"这条链路，
   不要把 `PIN_BTN = 4` 抄进 `config.h`。
2. **消抖逻辑直接复用**：`main.cpp` 里已有 `buttonPoll()`（20 ms 消抖 + 短按/长按），
   bring-up 里这段是它的简化版，事件语义一致。
3. **下一步建议按这个顺序**：
   - 把 `digitalWrite` 换成 LEDC PWM（`ledcSetup/ledcWrite` 或 `analogWrite`），先做"按键开/关"，再做"长按调光"；
   - 再加第二路（另一个颜色通道），验证双色混光；
   - 最后才接 IR 和舵机 —— 它们会抢电源和定时器，别一起上。

## 7. 边界

- 只用 3V3 给模块供电。**不要用 5V**：灯能亮，但按键模块的 `S` 会输出 5 V，超过 GPIO 的 3.6 V 耐压。
- 板载 3V3 LDO 余量够这两个模块（合计 < 20 mA），但带不动舵机；舵机要单独 5V 供电并共地。
- 本验证只证明"这块板 + 这两根线 + 这段代码"能工作，**不代表**成品 PCB 的引脚、限流、EMC 已确认。

## 8. 实测记录（2026-10-29，已跑通）

### 最终可用配置

| 连接 | 说明 |
|------|------|
| HW-479 `-` → ESP32 `GND` | 必须**直接**接地；挂在面包板蓝轨上不算数（蓝轨可能整条悬空） |
| HW-479 `G` → `GPIO5` | 共阴，高电平点亮；`R` / `B` 悬空 |
| HW-483 `+` → `3V3` | 模块自带 10k 上拉 |
| HW-483 `-` → `GND` | 必须和灯的 `-` 共用同一个接地点 |
| HW-483 `S` → `GPIO4` | 内部上拉 + 30 ms 消抖，按下读到 0 |

### 踩过的坑（按发生顺序）

1. **灯不亮**：`-` 接在面包板蓝轨上，而蓝轨没有真正连到 GND。
2. **按键也没反应，而且看不出来**：按键的 `S` 靠模块自带 10k 电阻上拉到 3V3，
   所以"松开读 1"在没接地时同样成立，故障被完全掩盖；只有按下去才会暴露。
3. **远程判断引脚是否带负载**（不用万用表）：
   - 内部下拉仍读到 1 → 该脚有**外部上拉**（典型：按键模块在线）
   - 内部上拉读到 0 → 该脚被**负载拉到地**（典型：LED 通道）
   两个方向各扫一遍，基本能还原接线。
4. **不要用"两脚反相"去兼容共阳/共阴**：公共端确认接地后，反相会让"灭"的状态下
   另一个通道常亮（红灯关不掉）。

## 9. 固件版本（MicroPython）

板上当前跑的是 MicroPython（YD 板出厂自带 1.19.1），不是 C++：

- `firmware/micropython/main_toggle.py`：短按开 / 关。**已验证可用**，出问题先退回它。
- `firmware/micropython/main.py`：短按开 / 关 + 长按切亮度档位（PWM 25/50/75/100 %）。
- `firmware/micropython/pin_probe.py`、`dual_test.py`：排查引脚和外接极性时用。
- 部署：`python tools/mp_deploy.py --port COM6 --remote main.py <文件>`

回退到纯开关版本：

```bash
python tools/mp_deploy.py --port COM6 --remote main.py firmware/micropython/main_toggle.py
```

**为什么不是 C++**：这台机器实测带宽约 16 KB/s，ESP32 Arduino 工具链约 1 GB，
按这个速度要十几个小时。C++ 版 bring-up 源码保留在 `firmware/src/bringup/main.cpp`，
换到正常网络后执行 `pio run -e bringup -t upload` 即可切回。
