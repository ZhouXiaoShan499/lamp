# 06 语音 AI 链路实施手册（任务一 / 二 / 三）

> 目标：在不接喇叭的前提下，把 **麦克风 → 局域网 → ASR → 本地大模型 → 文字回传**
> 整条链路跑通，并用串口输出证明每一环都真实工作。
> 本手册对应代码：`firmware/`（ESP32-S3）、`server/`（PC 端）。

---

## 零、验收标准（先写死，避免"感觉通了"）

| 任务 | 验收动作 | 通过标准 |
|------|----------|----------|
| 一、耳朵 | 串口执行 `mic probe`，再 `mic test 10` 说话/拍手 | `probe` 非零 > 90%；静音 RMS 稳定低于 `MIC_VAD_RMS`，说话/拍手跃升数倍并出现 `SPEECH` |

## 一、任务一：验证"耳朵"（ESP32-S3 + INMP441 I2S 麦克风）

### 1.1 接线

INMP441 是**标准 I2S** 麦克风，不是 PDM。SCK / WS / SD 三根信号线一根都不能省：
只接 SCK + SD（上一版 V829 PDM 的接法）读回来会恒为 0。

| INMP441 引脚 | ESP32-S3 | 说明 |
|--------------|----------|------|
| VDD | 3V3（+ 轨） | 1.8~3.3 V，**不要接 5V** |
| GND | GND（− 轨） | 与开发板共地，否则时钟会漂 |
| L/R | GND（− 轨） | 接地 = 左声道；代码固定读左槽，悬空时输出恒为 0 |
| SCK | GPIO16 | `PIN_VOICE_TX`，BCLK 位时钟（ESP32 输出） |
| WS | GPIO18 | `PIN_VOICE_WS`，LRCLK 声道时钟（ESP32 输出） |
| SD | GPIO17 | `PIN_VOICE_RX`，数据（麦克风 → ESP32） |

注意：

- **WS 最容易漏**：它和 SCK 一样是 ESP32 输出的时钟，不是"可选脚"。少了它，
  `mic probe` 会看到一片 0。
- 引脚名是历史遗留：`PIN_VOICE_TX/RX` 现在一个是 BCLK、一个是 SD，
  不要按 TX/RX 去接串口。
- **状态灯要给 WS 让位**：非面包板模式下 `config.h` 里 `PIN_STATUS_LED = 18`，正好撞 WS；
  面包板模式（`-DLAMP_BOARD_BREADBOARD=1`，`platformio.ini` 里已默认打开）
  已把它挪到 GPIO14。自己重排引脚时别把状态灯放回 18。
- 面包板蓝轨中间可能是断开的：VDD / GND 建议从开发板单独拉线，
  别只挂在轨上（这块板实测踩过，见 `docs/06-面包板点亮验证.md` §8）。
- 接线尽量短（< 10 cm）：16 kHz × 32 bit × 2 声道 ≈ 1 MHz BCLK，长线会和电源线串扰。

### 1.2 代码改动清单

| 文件 | 内容 |
|------|------|
| `firmware/include/config.h` | `LAMP_HAS_VOICE=1`；`MIC_SAMPLE_RATE=16000`、`MIC_FRAME_SAMPLES=512`、`MIC_GAIN=4`、`MIC_VAD_RMS` 等参数 |
| `firmware/include/pdm_mic.h` + `src/pdm_mic.cpp` | INMP441 驱动：IDF ≥ 5.0 用 `driver/i2s_std.h`（32 bit 槽读 24 bit 左对齐数据，右移 16 位取高 16 bit），更早核心回退 legacy `driver/i2s.h` |
| `firmware/src/voice_client.cpp` | 麦克风帧读取、RMS 计算、VAD、WebSocket 上报 |
| `firmware/src/main.cpp` | `mic on/off/test/probe`、`voice status/listen/say` 命令；补全 `setup()/loop()` |

采样率固定 16 kHz 单声道 16 bit，因为：

1. Vosk 小模型按 16 kHz 训练，改采样率会直接掉准确率；
2. INMP441 在 16 kHz 下 BCLK 约 1 MHz，功耗和干扰都低；
3. 32 ms 一帧（512 样本）刚好是 VAD 与网络发送的平衡点。

INMP441 的 24 bit 数据在 32 bit 槽里左对齐，若按 16 bit 槽读会错位成低频漂移，
所以驱动固定用 `I2S_DATA_BIT_WIDTH_32BIT`。实测说话峰值只有几十 LSB，
再乘 `MIC_GAIN`（默认 4）放大后才够 VAD 用；增益后的数据同时送给 Vosk，两头都不吃亏。

### 1.3 编译、烧录、观察

```powershell
cd firmware
pio run -e lamp_s3 -t upload
pio device monitor -b 115200
```

上电后应看到（节选，引脚号按面包板模式）：

```
=== LAMP-1 MVP firmware 0.1.0-mvp ===
[light] warm=21 cool=5 pwm=4000Hz bits=12
[motion] tilt=6 yaw=7 muted=0
[ir] receiver=9 sender=10
[mic] INMP441 I2S ready: 16000 Hz mono, BCLK=16 WS=18 SD=17
[voice] target ws://192.168.1.100:8765/ (16 kHz mono s16le)
```

先跑硬件自检（约 1.5 秒，不依赖网络）：

```
mic probe
```

```
[mic] ---------- INMP441 诊断 ----------
[mic] n=16000 均值=-3 min=-214 max=196 非零=99%
[mic] 有跳变：麦克风在出数，正常
[mic] ---------- 诊断结束 ----------
```

`非零` 比例明显低于 90%，或 min/max 全是 0，先按 1.4 查线，别急着看 VAD。

再跑电平监视：

```
mic test 10
```

然后安静 2 秒、拍手、正常说话。预期输出：

```
mic test: 10 s, clap or speak now
[mic] rms=    46 floor= 120 thr= 450 |........................................| quiet
[mic] rms=    52 floor= 118 thr= 450 |........................................| quiet
[mic] rms=   940 floor= 121 thr= 450 |###############.........................| SPEECH
[mic] rms=   268 floor= 130 thr= 450 |####....................................| noise
[mic] rms=   812 floor= 131 thr= 450 |#############...........................| SPEECH
mic test: done
```

通过标准：**静音行稳定低于 `thr`（默认 `MIC_VAD_RMS` = 450），拍手/说话跃升数倍并出现 `SPEECH`。**

数字只是参考，换麦克风/换房间要重新校准：`MIC_VAD_RMS` 取"静音 RMS × 3"，
且不低于 450（`config.h` 里 `MIC_VAD_RMS` 的注释就是这么来的）。

### 1.4 任务一排障

| 现象 | 优先检查 |
|------|----------|
| `mic probe` 全是 0 / `非零` 为 0% | WS(GPIO18) 或 BCLK(GPIO16) 没接；SCK 与 SD 接反；L/R 悬空；VDD 不是 3.3 V；I2S 通道打开失败（看启动日志 `[mic] ... failed`） |
| 所有行都是 `rms=0` | 同上；另外确认烧的是 `LAMP_HAS_VOICE=1` 的 `lamp_s3`，而不是 bringup |
| 数值恒定不变（如 32767 / -1） | SD 线被拉死或短路；模块没在出数（L/R 接错声道时长这样） |
| 数值有跳动但很小 | 麦克风离嘴太远；`MIC_GAIN` 偏小；供电纹波大 |
| 说话被条纹噪声淹没、`quiet` 行很高 | BCLK/WS 线太长或与电源线并排走；缩短到 10 cm 内、分开走线 |
| 一说话就重启 | 电源带不动 WiFi + 麦克风；换 USB 口/加大电容 |
| 编译报 `driver/i2s_std.h: No such file` | Arduino-ESP32 核心 < 3.0（IDF < 5.0）。代码本应自动走 legacy `driver/i2s.h` 分支，仍报这个说明版本宏判断异常，检查是否混用了两套驱动头文件 |


### 3.4 让它真的开灯（控制闭环）

文字回传只是"能聊天"，要让它**干活**，多一条 `cmd` 下行：

```
你说"开灯"
PC:   ASR → 开灯
      模型回答里带控制指令 <<LIGHT:on>>
      服务器把它转成 {"type":"cmd","light":"on"} 先发给 ESP32
ESP32: applyCommand() → lighting::setBrightness(70)，灯在 600 ms 内淡入
      串口打印 [cmd] light=on ...，随后打印模型那句话
```

支持的指令：

| 模型输出 | 效果 |
|----------|------|
| `<<LIGHT:on>>` / `<<LIGHT:on:80>>` | 开灯（默认 70%）/ 开到 80% |
| `<<LIGHT:off>>` | 关灯 |
| `<<BRI:50>>` | 只调亮度 |
| `<<CCT:4000>>` | 调色温 |
| `<<PRESET:night>>` | 切场景（study/office/rest/night） |

模型忘记写指令时，服务器用关键词兜底（开灯/关灯），所以这句话一定能用。

### 3.5 时序（便于排障）

```
ESP32: 麦克风 32ms 帧 ──RMS/VAD──▶ audio_start
       ──binary 帧流（每帧 512 samples）──▶
       静音 700ms ──▶ audio_end
PC:    Vosk 流式解码 ──▶ asr 事件 ──▶ Ollama（约 1~3 s）──▶ reply
ESP32: 打印 asr + reply，状态回到 Idle
```

任何一环断掉，串口和服务器日志都会留下明确标记：
`ws=down` / `audio_start` / `audio_end` / `reply in N ms` / `LLM failed`。

## 四、可调参数

| 参数 | 位置 | 默认 | 调整建议 |
|------|------|------|----------|
| `MIC_VAD_RMS` | `config.h` | 350 | 环境吵调到 700~1200；灵敏度不够降到 200 |
| `MIC_SILENCE_MS` | `config.h` | 700 | 说话停顿多调到 1000；想快调到 500 |
| `MIC_MAX_UTTERANCE_MS` | `config.h` | 8000 | 长句可到 12000，但延迟会上升 |
| `MIC_FRAME_SAMPLES` | `config.h` | 512 | 保持 512（32 ms），改小网络包变多 |
| `MIC_WAIT_REPLY_MS` | `config.h` | 45000 | 大模型换 14B 时调到 90000 |
| `--model` | 服务器 | `qwen3:14b` | 质量优先；换 `deepseek-r1:1.5b` 快约 10 倍但容易胡说 |
| `--max-seconds` | 服务器 | 15 | ESP32 单句上限 8 s，这里留余量 |
| `SYSTEM_PROMPT` | `voice_server.py` | 80 字短回答 | 想让它当"学习助手"就改这里 |

## 五、总排障表

| 层级 | 现象 | 处理 |
|------|------|------|
| 麦克风 | `mic test` 全 0 | 查接线/供电/SEL 脚；看启动日志 I2S 报错码 |
| WiFi | 串口无 `wifi_begin` 或一直重连 | `secrets.h` 是否被 include（`voice status` 显示 wifi=down）；2.4G/5G 是否同名 |
| WebSocket | `ws=down` 但 WiFi up | 服务器是否启动；IP/端口是否一致；防火墙 |
| ASR | `[ASR] heard: (empty)` | 声音太小/太短；`mic test` 看 RMS；把 `MIC_VAD_RMS` 降到 200 |
| ASR | 识别成乱码中文 | 采样率不是 16000；服务器 `--max-seconds` 太小截断 |
| LLM | `server error: LLM failed` | `ollama serve` 是否在跑；`ollama list` 是否有该模型；显存/内存是否够 |
| LLM | 回答带思考过程 | 已传 `think:false`，服务端会丢掉模型输出的思考段；仍出现就换模型 |
| 延迟 | > 15 s | 换更小模型/量化；关闭其他占内存程序；CPU 推理 1.5B 大约 1~3 s/句 |
